# 2026-10-06 — model 팔(bilinear Koopman Θ) Stonefish 런

`koopman_formation controller:=model|mpc` 검증 런. 오전 런(`koopman_model_sq4`, `*_leader_still_*`)은 공칭 Θ₀ + 그래디언트
확장 사전(ψ), 오후 런(`koopman_model_paper_sq4`)은 **원논문 형태**(φ 사전만·φ⁴ 제거·궤적 위 누적 재적합 Θ, 설명 노트 §11)
— 현재 노드의 model 팔은 후자다. 둘 다 제어 중 동결.
LiDAR 추정 기반, `formation.launch.py start_leader:=false` → S2 → `settle_wait` → `leader_pilot` 절차.
편대 오차는 `koopman_*.csv`의 GT 열(g0..g11, odometry 기준 상대상태)로 계산 — 이 환경에서 ros2 CLI가
SHM 프로파일 없이 토픽을 못 봐 정식 gate_s6는 돌리지 못했다.

**비교 기준 런(2026-10-06 오후, 연속 런).** 리더 플랫폼의 사각 주행 속도는 런마다 달라진다(녹화 200 s 시점 주행거리 12.0 /
14.6 / 16.9 m 등, 2026-08-16 노트의 미해결 현상 — CPU 부하 탓이라는 첫 추정은 틀렸다). 리더가 빠를수록 편대 유지가 어려우므로
**리더 주행거리 열을 같이 읽어야 한다**. 아래 MPC 런들은 analytic·model 런보다 리더가 20~40 % 빨랐는데도 오차가 작다(보수적 비교).

MPC(H=2) 5런은 중앙 0.139~0.155, p90 0.209~0.230 — analytic(0.162 / 0.272)보다 중앙 −4~−14 %, p90 −15~−23 %, 입력 사용은 같은
수준(|U| 중앙 0.040 vs 0.034); 원논문 꼴(0.190 / 0.360) 대비 중앙 −19 %, p90 −37 %. H=3 은 중앙이 더 낮지만 이득이 3배 높아
0.3 Hz 한계 사이클이 생기고 입력을 4배 쓴다(설명 노트 §12 튜닝 표).

**예측 스텝을 제어 틱보다 길게(`mpc_sub`, 2026-10-06 밤).** 지평을 늘리되 계산량은 그대로 두려고 리프팅 모델을 0.15 s(틱 3개, 입력 ZOH)
간격으로 식별해 썼다. 수치 시뮬에서는 지평 0.30~0.45 s가 코너 과도응답을 −8 % 줄였지만(설명 노트 §12), Stonefish 에서는 **이득을
스텝에 맞춰 λ=3 으로 올려야** 한다 — λ=1 이면 위치 기울기가 (0.15/0.05)² = 9배라 H=3·sub=1 과 똑같은 0.32 Hz 뱅뱅으로 돌아간다.
λ=3·지평 0.30 s 두 런은 리더 속도가 같은 기존 런보다 p90 −7 %(14.6 m)·−24 %(11.9 m, analytic 대비)로 기본 H=2 재런 범위의 아래쪽이고
입력은 같은 수준 — "같거나 조금 낫다". 지평 0.45 s 는 λ=3 에서도 입력 3배·사이클 잔존으로 진다. 기본값은 `mpc_sub` 1 그대로 두었다
(4런 근거 vs 2런); 바꾸려면 `mpc_sub:=3 mpc_horizon:=2 mpc_lam:=3 mpc_rho:=9`.

**공정 비교 ablation(2026-10-06 밤) — "MPC 이득은 이득(gain)이었나?"** MPC H=2·λ=1 은 U₀ 에 두 스텝 utility 가 걸려 analytic λ=1 보다 루프 이득이
~2배다. analytic 에 `qp_lam`(λ)·`qp_rho`(ΔU penalty, U = clip((c+ρU_prev)/(λ+ρ)))를 달아 이득·매끈함을 맞췄다.

읽기: (1) λ=0.5 analytic 은 λ=1 MPC 와 오차가 같다(0.146/0.212 vs 0.153/0.229) — **종전 "MPC가 analytic 을 15~23 % 이긴다"는 약한 기준선(λ=1)
덕이었다.** (2) λ·ρ 를 똑같이 맞춘 짝(λ=1·ρ=3, 리더 16.8~16.9 m)에서 MPC 는 p90·최대 −5~−9 %, 중앙 동률, 입력 같음(0.040 vs 0.037) — 이것이
horizon 의 실제 기여다. 수치 시뮬(analytic+ρ 코너 0.146~0.158 vs MPC 0.135)과 방향이 같고 크기는 작다. (3) 이득을 더 올리면(λ=0.5) analytic+ρ 는
사냥(|v_rel| 0.05), MPC 는 2런 중 1런 한계 사이클 — 둘 다 쓸 수 없는 영역. (4) 보강 dictionary 의 1-step QP 는 수치에서 analytic 보다 나쁘다
(코너 0.148 vs 0.136) — dictionary 만으로는 이득이 없고 H≥2 가 모델 오차를 메운다.

Koopman MPC 팔(최종 설정, 적합 시드 0·1)은 analytic 대비 edge 중앙 −13 % / −5 %, p90 −22 %, 최대 ±0 / −12 %, station 중앙 0.095·0.106 vs 0.147 m. 입력은 더 쓴다(|U| 중앙 0.09~0.11 vs 0.04, 포화 9~19 % vs 4 %)지만 부호 반전은 적다(11~13 % vs 18 %). 런 이력: 1차는 식별 영역 밖(워밍업 끝 오차 0.8 m) 외삽으로 10 s 만에 발산(CSV 미수록) → 2차 ρ=0 채터링 → 3차 ρ=3 + 신뢰 영역 폴백 → 4차 포화 좌표로 폴백 제거(시드 0 만 성공) → 적합 시드 1 발산 2회 → 최종: 포화 좌표 + 넓은 식별 데이터 + 폴백 복원.

논문 형태 팔은 analytic보다 edge 중앙 +0.02 m, p90 +0.08 m 나쁘다 — 수치 시뮬의 격차(정상 0.12~0.14 vs 0.08 m)와 같은 방향이고, 1차식 모델의 표현력 한계다(설명 노트 §5·§11). ψ 확장 사전은 analytic과 같지만 J의 미분을 사전에 넣은 동어반복이라 노드에서 뺐다.
